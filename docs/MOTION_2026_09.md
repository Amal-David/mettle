# September 2026 Motion update — experimental v0.3

## Release scope

The Figma announcement supplied on September 30 says **custom animation styles** and **Lottie export** are available now; **audio on the timeline** and **text animations** are rolling out the following week. That is the announcement's schedule, not a claim that every account or API has the forthcoming features today.

| Figma change | Mettle v0.3 |
|---|---|
| Custom animation styles | Compile attributable resolved tracks for supported properties. Style IDs/names need not be built-in. Preserve the original style metadata. Missing or partially resolved styles block export. Custom style code is never executed by Mettle. |
| Style timing/composition | Keep local key times plus their separate timeline offset. Preserve track order and additive/multiplicative operations. Additive slide styles no longer require a manual SET track. |
| Easing/timing variables | Resolve aliases against each consumer's effective variable mode. Preserve the original aliases and the resolved values in the export. A missing/cyclic/unavailable variable blocks export. Timing values remain seconds. |
| Back easing | Use the exact Figma-provided cubic, including overshoot; no generic replacement. Springs are still unsupported. |
| Figma's Lottie export | A different output path, not Mettle's input. Native loading now explains an accidental Lottie/dotLottie file. No Lottie dependency was added. |
| New text animations | **Not implemented.** Existing whole-node text movement/opacity still works with glyph outlines. This is not per-character/word/line animation support. |
| Audio on the timeline | **Not implemented.** No verified published capture contract for audio clips/assets/timing was available in the inspected API. Mettle must not claim an export has no audio merely because the API cannot inspect it. |

Unknown motion fields remain errors and are retained in `sourceMotion`. Unknown timeline fields now also block export instead of being discarded. `motionSupport` in the document and the plugin panel make the current boundaries explicit. An unavailable API is not an invitation to infer animation from rendered pixels.

## What the live probe found

In the project's Figma lab, frame `13:2` was created with a stacked entrance/exit/fade, a scale style, a rotation style, and Back easing. Existing golden frames `1:9` and `2:8` were not changed.

Immediately after applying styles in a single connector transaction, `animationStyles` existed but `animations` was empty. On a subsequent read, Figma exposed resolved tracks. Export therefore fails clearly until the source has actually resolved; it does not manufacture tracks from preset names.

The resolved tracks have an `animationPreset` annotation with an instance ID, duration and `timelineOffset`. Their key times are **style-local**, even though manual key times are timeline-relative. For an entrance placed at 0.2 seconds, the keys were 0 and 0.8; the exit at 1.5 seconds had keys 0 and 0.4. Both translation tracks used `OFFSET`. The opacity style used `SCALE`.

Figma's independent `get_motion_context` CSS confirms translation -24 px at 0/10%, 0 at 50/75%, and +24 at 95/100% of the two-second timeline. Mettle's Swift evaluator is tested at those times. The source snapshot fingerprint is `a7bea2c9`. The timing check is complemented by the bounded native-versus-Figma video comparison below; neither certifies arbitrary custom styles.

A separate temporary-variable probe confirmed `resolveForConsumer` returns the nondefault mode: the exact Back curve for an EASING token, and approximately 0.8 seconds for a TIMING token. All temporary variable resources were removed. The host does not allow setting scopes on those variable types; no scope change is required for export.

## Asset compatibility

v0.3 exports **scene schema version 2**. A track may now include `timelineOffset` in seconds; its keyframe `time` values stay local. The native evaluator subtracts placement before interpolation. This keeps multiple styles independently placed and avoids adding `props.delay` twice or applying duration scaling twice.

The updated runtime loads both schema versions 1 and 2. Old v0.2 runtimes deliberately reject version 2 rather than silently ignore placement. A version-1 document carrying a nonzero style offset is rejected as mislabeled. Update the Figma plugin **and** the native library together. The `.figmetal.json` extension and `figma-metal` format identifier remain unchanged.

Source rotation/scale pivots still carry the existing verification warning. Translation with a non-SET leading SCALE operation remains blocked. Unknown easing names, springs, shader effects and other unsupported native operations remain blocked. Resolved custom styles are supported only within this explicit subset, not universally.

## Evidence and remaining gates

Local Linux validation: **56 JavaScript tests, 40 Swift core tests, and 5 comparison-harness tests passed**. That includes 20 new JavaScript tests and 11 new Swift tests. The new source fixture compiles and loads through the actual JS compiler → Swift decoder/evaluator. The standalone generated plugin is executed under a mocked host as well as testing the separate modules.

The development Mac reconnected before publication. **140 automated tests passed on the Apple M4 Pro**: 56 exporter/capture, 40 Swift core, 17 actual GPU, 1 native renderer-host, 21 preview/playback/reference, and 5 comparison-measurement. Metal API Validation was enabled. Three new GPU tests check the delayed fade, separately placed exit, and repeatable seeking of combined styles. The existing six live-reference regression gates still pass. The native executable builds, and the `Mettle` library compiles for arm64 iOS simulator.

Figma independently exported frame `13:2` as a 600×320 H264 video at 10 fps. All **21 endpoint-inclusive frames** were compared with native Metal output. Worst per-frame RGB mean absolute error was **1.637014 / 255**, worst regional RGB mean error **2.131886 / 255**, and maximum threshold-detected boundary difference **2 pixels**. The comparison covers this one entrance/exit/fade/scale/rotation/Back scene only. H264 compression and rasterizer edges differ; this is not pixel-perfect certification or general pivot parity. The reference is hash-locked and is never read by the renderer.

The original video is in `fixtures/motion-2026/styles.reference.mp4`; complete per-frame measurements are in [motion-2026-comparison.json](motion-2026-comparison.json). `./scripts/verify_live.sh` now reproduces both the previous corpus and this additional comparison. Logs remain on the development Mac under `artifacts/motion-2026/`.

Physical-iPhone execution, interaction with the new native preview UI, and the complete Figma Desktop install/export-panel flow were **not manually revalidated**. The renderer was not replaced or converted to video playback. GitHub's Apple job checks core/playback/reference tests and Mac/iOS compilation, not physical GPU fidelity; consult the checks on the actual commit.

A user-authored custom-style production file still needs end-to-end visual verification. The current live corpus uses actual Figma styles; an additional opaque-ID fixture checks custom IDs without a name whitelist. The upcoming audio/text APIs need real exported source specimens and independent references before support can be advertised.
